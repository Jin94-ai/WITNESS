테스트 코드를 생성합니다.

대상: $ARGUMENTS

## 사전 확인 (Feedforward)

1. 대상 파일을 읽어 실제 함수 시그니처와 동작을 파악한다
2. 프로젝트의 테스트 프레임워크를 확인한다 (package.json, pytest.ini, setup.cfg 등)
3. 기존 테스트 파일이 있으면 읽어 패턴을 파악하고 일관성을 유지한다

## 테스트 유형

1. **Unit Test** — 개별 함수/메서드, Mock/Stub 활용
2. **Integration Test** — 모듈 간 상호작용
3. **Edge Cases** — 빈 값, null/undefined, 경계값, 에러 케이스

## 테스트 작성 원칙

- AAA 패턴: Arrange → Act → Assert
- 테스트 이름은 "무엇을 하면 어떻게 된다"로 명확하게
- 하나의 테스트에서 하나의 동작만 검증
- 실제 코드와 동기화: 존재하지 않는 함수는 테스트하지 않는다

## 출력

1. 테스트 케이스 목록 (커버하는 시나리오)
2. 완성된 테스트 코드
3. 실행 명령어
4. 예상 커버리지

## 자가 체크 (Feedback)

- [ ] 테스트가 실제 코드의 함수 시그니처와 일치하는가?
- [ ] Mock이 실제 의존성과 동일하게 동작하는가?
- [ ] 엣지 케이스(null, 빈 배열, 최댓값)가 포함되었는가?
- [ ] 테스트가 독립적으로 실행 가능한가? (순서 의존성 없음)
